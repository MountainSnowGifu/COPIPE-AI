Claude Code は、CLIで動くエージェント型コーディングツール
コードを提案するだけでなく、実際にファイルを読み、編集し、コマンドを実行する。
基本の仕組みは「Claudeモデル + ツール群」
Claudeモデルが判断する。
ファイル操作、検索、シェル実行、Git操作、テスト実行などのツールを使う。
動作の流れは「読む → 考える → 編集する → 実行する → 確認する」
コードベースを調査する。
必要な修正を行う。
テストやlintを実行する。
結果を見て再修正する。
普通のコード補完とは違う
補完AIは「今書いているコードの続きを出す」。
Claude Code は「バグ修正やリファクタリングなどの作業単位を進める」。
CLAUDE.md が重要
プロジェクトのルールや開発手順を書いておく指示書。
例：テストコマンド、コーディング規約、ディレクトリ構成、PRルールなど。
コンテキスト管理をしている
会話、読んだファイル、コマンド結果、プロジェクト指示をもとに判断する。
長い作業では古い情報が圧縮されることがある。
権限管理がある
ファイル編集やコマンド実行の前に確認を求める設定がある。
自動承認モードもあるが、危険な操作には注意が必要。
チェックポイントで巻き戻せる
ファイル変更前の状態に戻せる。
ただし、DB操作や外部API呼び出しなどの副作用までは戻せない。
MCP、Hooks、Skills、Subagents で拡張できる
MCP：外部サービスや社内ツールと接続。
Hooks：特定のタイミングでコマンドを自動実行。
Skills：よく使う作業手順を再利用。
Subagents：別コンテキストで専門的な作業を任せる。
得意なこと
バグ調査。
複数ファイルの修正。
テスト追加。
リファクタリング。
ドキュメント更新。
Git操作やPR準備。
苦手・注意点
仕様を誤解することがある。
テストが弱いと間違った修正でも通る。
本番DBや外部API操作は危険。
長時間作業では指示を忘れることがある。
安全な使い方
まず Plan mode で調査・計画だけさせる。
その後に実装させる。
差分を必ずレビューする。
CLAUDE.md にルールを書く。
テストとGitを必ず使う。
